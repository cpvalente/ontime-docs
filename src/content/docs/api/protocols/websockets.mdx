---
title: WebSockets API
description: "Control Ontime and receive live runtime updates over WebSocket: playback, event changes, stage timer messages and auxiliary timers, with JSON messages."
---

Ontime's own views use the WebSocket API, so it is always on. It runs at the same address and port as Ontime:

```bash
ws://<ip-address>:<port>/ws
# eg. ws://192.168.1.10:4001/ws
```

- On Ontime Cloud, use `wss://cloud.getontime.no/<stage>/ws`.
- When a client connects, Ontime sends a snapshot of the [runtime data](/api/data/runtime-data/), then sends updates as they happen.
- Every message is JSON with a `tag` (the action) and, for most actions, a `payload`. Replies use the same `tag`.

```json
{"tag": "start", "payload": "next"}
```

## Read state

| Message | Reply payload |
| :--- | :--- |
| `{"tag": "version"}` | The Ontime version, eg. `"4.15.1"` |
| `{"tag": "poll"}` | A snapshot of the [runtime data](/api/data/runtime-data/) |

## Playback

| Action | Message |
| :--- | :--- |
| Start the loaded event | `{"tag": "start"}` |
| Start the next event | `{"tag": "start", "payload": "next"}` |
| Start the previous event | `{"tag": "start", "payload": "previous"}` |
| Start an event by position (from 1) | `{"tag": "start", "payload": {"index": 3}}` |
| Start an event by ID | `{"tag": "start", "payload": {"id": "<event-id>"}}` |
| Start an event by cue | `{"tag": "start", "payload": {"cue": "<cue>"}}` |
| Load an event | `{"tag": "load", ...}`, with the same payloads as `start` |
| Pause | `{"tag": "pause"}` |
| Stop | `{"tag": "stop"}` |
| Reload the current event | `{"tag": "reload"}` |
| Start [Roll mode](/quick-tips/roll/) | `{"tag": "roll"}` |
| Add time to the running event | `{"tag": "addtime", "payload": {"add": <milliseconds>}}` |
| Remove time from the running event | `{"tag": "addtime", "payload": {"remove": <milliseconds>}}` |

You can add or remove up to one hour at a time.

## Change an event

Send the event ID with the fields to change. See the [fields you can change](/api/data/event-data/#fields-you-can-change-over-the-api).

```json
{
  "tag": "change",
  "payload": {
    "<event-id>": {
      "title": "New title",
      "custom:<field-name>": "new value"
    }
  }
}
```

## Messages

Control the messages on the [stage timer](/interface/automated/stage-timer/) view.

| Action | Message |
| :--- | :--- |
| Set the [secondary message](/features/secondary-message/) | `{"tag": "message", "payload": {"secondary": "<text>"}}` |
| Set the timer message | `{"tag": "message", "payload": {"timer": {"text": "<text>"}}}` |
| Show or hide the timer message | `{"tag": "message", "payload": {"timer": {"visible": true}}}` |
| Make the timer message blink | `{"tag": "message", "payload": {"timer": {"blink": true}}}` |
| Black out all stage timer screens | `{"tag": "message", "payload": {"timer": {"blackout": true}}}` |
| Choose what shows in the secondary field | `{"tag": "message", "payload": {"timer": {"secondarySource": "<source>"}}}` |

`<source>` is `secondary` for the secondary message, or `aux1`, `aux2` or `aux3` for an auxiliary timer. Any other value, such as `"off"`, hides the secondary field. \
You can combine several fields in one message.

The reply payload is the current message state:

```json
{
  "secondary": "new text",
  "timer": {
    "text": "",
    "visible": true,
    "blink": false,
    "blackout": false,
    "secondarySource": "secondary"
  }
}
```

## Auxiliary timers

Ontime has three [auxiliary timers](/features/aux-timer/), numbered `1` to `3`. They run separately from the rundown.

| Action | Message |
| :--- | :--- |
| Start | `{"tag": "auxtimer", "payload": {"1": "start"}}` |
| Pause | `{"tag": "auxtimer", "payload": {"1": "pause"}}` |
| Stop | `{"tag": "auxtimer", "payload": {"1": "stop"}}` |
| Set the duration | `{"tag": "auxtimer", "payload": {"1": {"duration": <milliseconds>}}}` |
| Count up or down | `{"tag": "auxtimer", "payload": {"1": {"direction": "count-up"}}}` |
| Add time (negative to remove) | `{"tag": "auxtimer", "payload": {"1": {"addtime": <milliseconds>}}}` |

The reply payload is the timer's new state.
