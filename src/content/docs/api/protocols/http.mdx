title: HTTP API
description: "Control Ontime with simple HTTP GET requests: start, load and stop events, change event fields, set stage timer messages and control auxiliary timers."
---

Control Ontime with simple **GET** requests, for example from [vMix](/quick-tips/integrate-with-vmix/), a browser or a script.

```bash
GET http://<ip-address>:<port>/api/<action>
# eg. http://192.168.1.10:4001/api/start/next
```

- On Ontime Cloud, use your stage link instead of `<ip-address>:<port>`.
- Encode spaces and special characters in values, eg. `New%20title`.
- A successful request returns status `202` and `{"payload":"success"}`, unless the tables below say otherwise.

## Read state

| Request | Returns |
| :--- | :--- |
| `/api/version` | The Ontime version, eg. `{"payload":"4.15.1"}` |
| `/api/poll` | A snapshot of the [runtime data](/api/data/runtime-data/) |

To read project data, use these requests (without `/api`):

| Request | Returns |
| :--- | :--- |
| `/data/rundowns/current` | The current rundown |
| `/data/rundowns` | All rundowns in the project |
| `/data/project` | Project data |
| `/data/custom-fields` | [Custom fields](/features/custom-fields/) |
| `/data/settings` | Application settings |
| `/data/view-settings` | Settings for views |
| `/data/url-presets` | [URL presets](/features/url-presets/) |
| `/data/automations` | [Automations](/api/automation/) |
| `/data/report` | The current session report |
| `/data/session` | Current session stats |
| `/data/db` | The whole project file |

## Playback

| Action | Request |
| :--- | :--- |
| Start the loaded event | `/api/start` |
| Start the next event | `/api/start/next` |
| Start the previous event | `/api/start/previous` |
| Start an event by position (from 1) | `/api/start/index/<position>` |
| Start an event by ID | `/api/start/id/<event-id>` |
| Start an event by cue | `/api/start/cue/<cue>` |
| Load the next event | `/api/load/next` |
| Load the previous event | `/api/load/previous` |
| Load an event by position (from 1) | `/api/load/index/<position>` |
| Load an event by ID | `/api/load/id/<event-id>` |
| Load an event by cue | `/api/load/cue/<cue>` |
| Pause | `/api/pause` |
| Stop | `/api/stop` |
| Reload the current event | `/api/reload` |
| Start [Roll mode](/quick-tips/roll/) | `/api/roll` |
| Add time to the running event | `/api/addtime/add/<milliseconds>` |
| Remove time from the running event | `/api/addtime/remove/<milliseconds>` |

You can add or remove up to one hour at a time.

## Change an event

Add the fields to change as query parameters. See the [fields you can change](/api/data/event-data/#fields-you-can-change-over-the-api).

```bash
# Change the title
GET http://<ip-address>:<port>/api/change/<event-id>?title=Keynote

# Change a custom field
GET http://<ip-address>:<port>/api/change/<event-id>?custom:<field-name>=new-value

# Change several fields at once
GET http://<ip-address>:<port>/api/change/<event-id>?title=Keynote&cue=12
```

## Messages

Control the messages on the [stage timer](/interface/automated/stage-timer/) view.

| Action | Request |
| :--- | :--- |
| Set the [secondary message](/features/secondary-message/) | `/api/message/secondary/<text>` |
| Set the timer message | `/api/message/timer?text=<text>` |
| Show or hide the timer message | `/api/message/timer?visible=true` or `false` |
| Make the timer message blink | `/api/message/timer?blink=true` or `false` |
| Black out all stage timer screens | `/api/message/timer?blackout=true` or `false` |
| Choose what shows in the secondary field | `/api/message/timer?secondarySource=<source>` |

`<source>` is `secondary` for the secondary message, or `aux1`, `aux2` or `aux3` for an auxiliary timer. Any other value, such as `off`, hides the secondary field.

Message requests return the current message state:

```json
{
  "secondary": "new text",
  "timer": {
    "text": "",
    "visible": true,
    "blink": false,
    "blackout": false,
    "secondarySource": "secondary"
  }
}
```

## Auxiliary timers

Ontime has three [auxiliary timers](/features/aux-timer/), numbered `1` to `3`. They run separately from the rundown.

| Action | Request |
| :--- | :--- |
| Start | `/api/auxtimer/1/start` |
| Pause | `/api/auxtimer/1/pause` |
| Stop | `/api/auxtimer/1/stop` |
| Set the duration | `/api/auxtimer/1/duration/<milliseconds>` |
| Count up or down | `/api/auxtimer/1/direction/count-up` or `count-down` |
| Add time (use a negative value to remove time) | `/api/auxtimer/1/addtime/<milliseconds>` |

Auxiliary timer requests return the timer's new state.
